# 구현 인수인계

## 기준과 주소 표기

원본은 [rom.json](../config/rom.json)의 일본판입니다. 영어 번역 ROM은 초기에 비교 자료로 사용했지만, 공개 빌드에는 필요하지 않으며 코드·문장·그래픽을 가져오는 입력으로 사용하지 않습니다.

`0x00xxxx` 같은 파일 오프셋에는 16바이트 iNES 헤더가 포함됩니다. `$xxxx`는 CPU 또는 PPU 주소이고 문맥에 명시합니다. PRG가 뱅킹되므로 모든 CPU 주소를 하나의 전역 공식으로 파일 오프셋에 바꿀 수 없습니다. 원본 첫 PRG 영역의 CPU `$8000`은 파일 `0x10`, 확장 결과의 고정 CPU `$C000`은 파일 `0x3C010`입니다. CHR 파일 기준점도 원본 `0x20010`에서 결과 `0x40010`으로 바뀝니다.

## 텍스트의 구조

본문·설정·상점은 PPU 주소 두 바이트와 문자열, `FE` 다음 행, `FF` 레코드 끝으로 구성되는 경로가 있습니다. 스태프롤은 별도의 위치 바이트와 행 이벤트를 씁니다. `rom_text.py`는 이 두 형식을 구분합니다. 글자로 보이는 숫자나 ASCII가 실제로는 로고 타일일 수 있습니다.

공개 표는 168개 행이며 `jp_text_offset`이 줄의 안정적인 키입니다. `jp_record_offset`은 같은 화면/명령에 속하는 줄을 묶습니다. 숫자 토큰, 공백 유지, 로고 유지 상태를 일반 문장과 구분합니다. 번역과 화면 배치를 분리하고 승인된 줄바꿈은 별도 JSON으로 기록했습니다.

## 메모리 배치

| 영역 | 배치 | 설명 |
| --- | --- | --- |
| PRG 전체 | 128 → 256 KiB | MMC3 유지; 원본 고정 뱅크를 새 끝에 복사하고 기존 사본도 보존 |
| CHR 전체 | 128 → 256 KiB | 화면 계열별 한국어 글꼴 추가 |
| PRG bank 16 | `0x20010` | 오프닝·엔딩 문장 스트림 |
| PRG bank 17 | `0x22010` | 설정 문자열과 선택 테이블 |
| PRG bank 18 | `0x24010` | 한국어 스태프롤 이벤트 |
| PRG bank 19 | `0x26010` | 상점 스트림·가변 숫자 테이블 |
| CHR `$80/$82` | `0x60010` | 오프닝 글꼴 |
| CHR `$84/$86` | `0x61010` | 엔딩 본문 글꼴 |
| CHR `$88/$8A` | `0x62010` | 설정 글꼴 |
| CHR `$8C/$8E` | `0x63010` | 스태프롤 글꼴·원본 로고 |
| CHR `$90/$92` | `0x64010` | 상점 글꼴 |
| CHR `$98..$AB` | `0x66010`부터 | 그림용 기존 패턴 복제와 자막, 각 4 KiB |
| CHR `$1C` 안의 타일 `$10..$3F` | `0x47110..0x4740F` | 도스명조 이름용 48개 8×8 패턴 |

CHR 뱅크 번호는 1 KiB 단위입니다. MMC3의 2 KiB 레지스터 쌍과 혼동하지 마세요. 정확한 현재 사용량과 변경 주소는 각 빌드의 로컬 `manifest.json`에 기록됩니다.

## 주입 코드와 연결 지점

| CPU 주소 | 역할 |
| --- | --- |
| `$A97D` | 본문 렌더러와 그림/문장 글꼴 전환 |
| `$AA00` | 설정 제목·전체 행 갱신 |
| `$AB20` | 스태프롤 두 타일 행 이벤트 |
| `$AB90` | 상점 출력 분기·가변 값 읽기·갱신 |
| `$ACD8` | 그림 자막·엔딩 카드 IRQ 경계 보정 |
| `$97F1`부터 | 이전 일본어 스태프롤 데이터 영역을 자막 명령용으로 회수 |
| 고정 뱅크 `$F340` | 스테이지 이름 스프라이트 렌더러·인트로 우선순위 |
| 고정 뱅크 `$F400` | 스테이지별 x/y/타일 목록 |
| `$D772` | 이름 출력 경로를 새 렌더러로 연결 |
| `$E256` | 활성 인트로 동안만 스프라이트 할당 방향 고정 |

새 렌더러는 원래 로직을 전역 교체하기보다 해당 화면의 호출부를 연결합니다. 원래 선택값·구매·차감·보유 수량·난이도 분기는 유지합니다. 뱅크 변경 전 원래 값을 스택에 보관하고 반환 전에 복구합니다. 빈 공간처럼 보이는 곳도 마지막 경계와 다른 주입 코드의 끝을 assert로 검사합니다.

## 본문·설정·상점

한글은 8×16, 두 개의 8×8 타일입니다. 일반 본문 시작은 타일 행 17이며 일부 페이지는 19/21에서 시작합니다. 한 줄 28셀 안에서 사용자가 검토한 줄바꿈을 사용합니다. 처음부터 새 폰트를 통째로 넣지 않고 해당 화면에서 사용하는 패턴을 중복 제거합니다.

설정값은 0/1만 오는 것으로 가정하지 않습니다. 실제 우선순위 플래그는 `$FF`가 될 수 있어 원본과 같이 0/비0으로 해석합니다. 숨겨진 옵션의 원래 게이트 `$FFF9`는 유지합니다. 값의 길이가 줄어드는 경우 이전 두 타일 행을 모두 지웁니다.

상점 필드는 RAM에서 읽어 표시합니다. 대표적으로 `$018E` 소지금, `$34+1` 무기 번호, `$33` 무기 단계, `$3C+1` 연사 단계, `$0178`부터 배송 슬롯입니다. 표시용 숫자 생성과 실제 게임 값 변경을 섞지 않습니다. 단위 없는 숫자만 맞추지 말고 개수 숫자와 `엔`의 열을 각각 정렬합니다. 최대 폭탄 안내의 불필요한 빈 행은 레이아웃에서 제거했습니다.

## 스태프롤

원래 이벤트 순서·공백 이벤트·회사 로고를 유지합니다. 글자의 상하 타일을 각각 32바이트 패킷으로 보내 원래 PPU 큐의 한 번 전송 한도를 넘지 않도록 했습니다. 43개 텍스트 레코드뿐 아니라 8개의 세로 스크롤 픽셀 위상에서 검사했습니다. 정지 화면의 글자가 맞아도 중간 위상의 CHR/스크롤 경계는 틀릴 수 있습니다.

## 그림 자막과 엔딩

원본 그림에서 사용 중인 타일을 먼저 찾아 보존하고, 복제한 CHR 뱅크의 사용하지 않는 타일에 자막을 넣습니다. 그림 안 일본어를 지우지 않습니다. 자막 셀은 y=8–23입니다. 일반·하드·이판사판 카드만 y=16에서 y=32로 이동하고 로봇과 오프닝 그림은 기존 위치를 유지합니다.

세 엔딩 카드는 스태프롤이 끝난 뒤 START를 누르면 나타납니다. 그때만 그림/글꼴 전환 IRQ를 16px 늦추고 하단 원본 위치를 보정합니다. 진행 중 스태프롤과 마지막 회사 로고를 함께 내리지 않습니다. 원본 그림 색을 지키기 위해 엔딩에는 미사용 팔레트 3을 쓰고, 오프닝은 기존 회색 그림자 팔레트를 씁니다.

## 스테이지 이름

8×16 스프라이트 두 개가 한글 한 글자를 이룹니다. 13개 한글의 조각 26개 중 동일 조각을 공유하여 24개 조각, 즉 48개 8×8 타일을 사용합니다. `나`/`내`의 왼쪽, `태`/`내`의 오른쪽 같은 공유는 비트맵 일치로 판정하며 이름만 보고 합치지 않습니다. AREA/CLEAR 공용 타일 `$00..$0F`는 보존합니다.

1–6 구역과 7–8 구역은 같은 패턴을 다른 PPU 위치로 매핑하므로 스프라이트 타일 번호의 보정값이 각각 0과 `$C1`입니다. 마지막 이름의 둘째 줄은 y=128, 첫째 줄은 y=104입니다. 공백 8px를 포함한 전체 폭으로 중앙 정렬합니다.

한 줄 최대 8개 스프라이트라서 별 배경과 합치면 하드웨어 표시 한도를 넘을 수 있습니다. 원본의 OAM 할당 방향이 번갈아 바뀌는 동안 글자 획이 깜빡였습니다. `$0188`이 1–125인 활성 인트로 동안만 정방향 할당으로 글자를 먼저 표시하고, 인트로가 끝나면 기존 순서를 사용합니다. 같은 높이의 별 일부가 생략될 수 있지만 한글 획은 유지됩니다.

## 이어서 작업할 때

전체 정상 플레이로 8구역을 클리어한 검증, 실기, 다른 에뮬레이터는 아직 남아 있습니다. 현재 자동 검증은 실제 렌더러를 호출하지만 구역 선택·CLEAR·엔딩 직행에는 명시적인 로컬 테스트 fixture를 씁니다. 이를 배포 ROM에 적용하지 마세요. 이 빌드의 주소는 다른 게임·리비전에 그대로 적용할 수 없습니다.
